## Methodology

- **Tooling**: stdlib only (`random`, `signal`, `hashlib`, `json`, `traceback`, `itertools`, `struct`, `argparse`). No AFL, no libFuzzer, no Atheris — the target is pure Python, so instrumentation-based sanitizers add no signal beyond what `random`+`signal.alarm(5)` already provides.
- **Determinism**: every run uses an explicit `random.seed(N)` so re-runs are bit-identical (`last_input_hash` recorded in each `stats.json`).
- **Per-input timeout**: `signal.alarm(5)` inside each harness; a hang in user-space Python would trip the alarm and surface as a hang in `hangs/<id>.in`. None observed.
- **Crash capture**: uncaught exceptions of any kind (`AttributeError`, `TypeError`, `NameError`, `KeyError`, `IndexError`, raw `ValueError` not via `CrockfordBase32Error`, etc.) write the raw input to `crashes/<id>.in` and the traceback to `crashes/<id>.stacktrace`. None observed.
- **Schema of `stats.json`**: per-surface JSON dict with `iterations`, `crashes`, `hangs`, surface-specific counters (round-trip mismatches, validate_total_violations, negative_int_not_caught, etc.), `last_input_hash`, `seed`. Note: the harnesses do not currently record `elapsed_seconds` in stats.json (a card-02 schema gap); wall-clock was measured externally with `date +%s.%N` and is reported in the table below.
- **Seed corpus**: each `fuzz/<surface>/corpus/SEEDS.md` (78 cells total) was loaded by the harness as the first inputs; subsequent inputs are randomly generated by the surface-specific strategy.
